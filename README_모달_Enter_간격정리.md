# 모달 Enter 처리와 UI 간격 정리

2026-10-15. 실행 코드 변경: `js/studio.js`, `style.css`. 새 실행 모듈과 라이브러리는 없습니다.

## 모달 키보드 동작

기존 코드는 dialog의 keydown 전파만 막고 브라우저 기본 동작은 허용했습니다. 그 결과 취소/닫기 버튼에 포커스가 있으면 Enter가 그 버튼을 실행했습니다.

Enter 기본 동작을 취소하고 기존 `finish(true)` 수락 경로로 연결했습니다. 별도의 수락/검증 로직은 만들지 않았습니다.

- Enter: 입력창·확인·취소·닫기 중 어디에 포커스가 있어도 수락.
- 잘못된 필수값/숫자 범위: 기존 `reportValidity()`가 수락을 막고 모달을 유지.
- 한글 조합 중 Enter와 keyCode 229: 수락 처리하지 않음.
- 누르고 있는 Enter의 반복 이벤트, Ctrl/Cmd/Alt+Enter: 기본 버튼 실행을 막되 수락하지 않음.
- Esc, 취소/닫기 버튼 클릭: 취소 유지. 취소 버튼에 포커스 후 Space도 네이티브 취소 동작 유지.
- form submit과 확인 버튼 클릭: 기존 수락 경로 유지.

Enter는 현재 포커스된 버튼을 실행하는 키가 아니라 모달 수락 키로 일관되게 동작합니다. 취소는 Esc 또는 취소 버튼 클릭/Space를 사용합니다.

## 간격과 시각적 정리

본문 간격을 각 자식의 margin이 아니라 부모 컨테이너가 소유하도록 정리했습니다.

| 영역 | 적용한 기준 |
| --- | --- |
| 접힘 도구 제목 | 열린 상태의 배경·하단 경계선으로 본문과 구분 |
| 도구 본문 | 상단 12px, 좌우 14px, 하단 16px padding |
| 본문 항목 사이 | Grid gap 12px. 직접 자식 margin은 0으로 정리 |
| 패스 연결 | 첫 카드 위 본문 여백 확보, 카드 사이 8px, 카드 내부 10×12px |
| 연결 카드 설명 | 제목과 설명 사이 4px, 설명 행간·대비 조정 |
| 채널 입력 | 채널 사이 8px. 행별 bottom margin 제거 |
| 예제·파일 버튼 | 개별 top/bottom margin 제거, 부모 gap 사용. 파일 버튼 사이 8px |
| 이미지 목록 | 목록 바깥 margin 제거, 항목 사이 8px, 카드 내부 10px |
| 픽셀 검사 | 라벨·출력·설명 사이 공통 gap, 출력 내부 12px |
| 보조 코드 도구 | 펼친 도구 내부 padding 10/12/12px와 gap 8px |
| 파라미터 | 카드 사이 12px, 카드 제목 아래 12px, 값 입력 사이 8px |
| 모달 | 헤더 20px, 입력 영역 좌우/하단 20px, 액션 영역 16×20px, 버튼 최소 높이 40px |
| 짧은 모달 | 비어 있는 설명 문단 숨김, 제목의 불필요한 bottom margin 제거 |

특정 카드에 margin-top을 임시로 더하지 않았습니다. 패스 연결처럼 설명 문단 없이 첫 카드부터 나오는 영역도 동일한 본문 여백을 받습니다. 기존 button margin 규칙 두 개와 첫 설명 문단의 별도 여백 규칙을 제거하여 gap과 중복되지 않게 했습니다.

## 검증

- `node tests/modal-enter-regression.js`: 14개 동작 검사. 포커스별 수락, 기본 버튼 실행 방지, 숫자 검증, IME, 반복/수정키, 취소, 확인 모달, 일반 submit.
- `tests/workspace-layout-regression.js`: 공통 본문의 상단 여백/간격, 자식 margin 초기화, 버튼 중복 margin 방지 검사 추가.
- 기존 검사를 포함한 Node 19개 스위트, JS/Python 구문, 소스 해시, ZIP 무결성 검사 통과.
- `tests/autopair-browser-regression.py`에 실제 Enter 키로 포커스별 모달 수락과 잘못된 줄 번호의 수락 방지 검사를 추가했습니다. 실행 가능한 브라우저가 없는 환경이므로 이 브라우저 검사는 이번에 실행하지 않았습니다.
- 자동 동작 검사는 실제 모듈과 모의 DOM/WebGL을 사용합니다. 실제 브라우저의 네이티브 기본 동작·최종 픽셀 간격·시각적 완성도를 직접 검증한 것으로 해석하지 않습니다.
