# 앱 공통 메뉴 명령

메뉴 바·바탕/뷰포트 우클릭·더보기/캡처 메뉴·명령 팔레트에서 반복되는 앱 명령을 점검한다.
파라미터·타임라인 키·편집기 심볼처럼 선택한 객체에 따라 달라지는 작업은 해당 모듈이 관리한다.

점검에서 확인한 불일치는 편집기의 이름 차이, 고정된 배치/전체화면/분리 창 동작 이름,
버튼 본문에 섞인 단축키·파일 형식, 팔레트의 같은 동작 중복, 분리 창 배경의 요소 판별이었다.

## 이름과 상태

| 항목 | 표시 기준 |
|---|---|
| 설정 패널·셰이더 편집기·타임라인·HUD | 공통 이름과 실제 버튼의 `aria-pressed`/`aria-expanded` 체크 상태 |
| 재생·녹화·전체화면·미리보기 분리·테마 | 버튼의 현재 동작 이름을 읽어 메뉴를 열 때 갱신 |
| 편집기 배치 | 원본 버튼이 안내하는 다음 배치 이름과 `Ctrl+\` |
| 명령 팔레트 | 상태 변화에 관계없이 검색할 수 있는 고정 명령 이름 |
| 메뉴 바 복구 | 이름 `메뉴 바 보이기`, 별도 단축키 `F10` |

반복되는 이름·단축키·체크 상태는 `js/menu-commands.js`가 정의한다.
`menu-bar.js`와 `app-menus.js`는 메뉴 순서·묶음·아이콘·편집기 열기 등의 전처리를 맡는다.
더보기/캡처는 메뉴를 열기 전에 같은 정의로 본문을 갱신하고, 기존 버튼과 이벤트를 유지한다.

이름을 버튼에서 가져올 때 `aria-label`을 우선하며, 본문을 읽어야 하면 `kbd`·SVG·장식 요소를 제외한다.
`kbd`에는 파일 형식·배율·녹화 형식도 들어 있으므로, 그것을 실제 단축키로 자동 등록하지 않는다.
단축키 정의는 기존 키 처리에 맞춘다. `Space` 등 입력 위치에 따라 동작하는 키의 조건은 유지한다.

## 실행과 팔레트 중복

메뉴는 열 때 비활성 상태를 읽고, 선택할 때 원본 버튼의 존재·비활성·숨김 상태를 다시 확인한다.
의도적으로 숨겨 둔 실행 버튼을 사용하는 메뉴는 `keepHidden`으로 명시한다.

같은 동작의 별도 버튼(`studioPause`/`previewPause`, `studioHelp`/`helpToggle`, `quickShot`/`screenshotButton`)은
공통 명령 ID로 연결한다. 팔레트에서 저장·버전 기록·미리보기 분리도 ID를 등록하여 중복을 피한다.
팔레트 항목 이름의 메뉴 경로와 편집기 키 바인딩은 각 등록 위치에서 관리한다.

## 검증

- `menu-consistency-browser-regression.js`: 다크·라이트 테마, 메뉴 간 이름/단축키/체크 비교, 상태 변경 후 재열기, 팔레트 중복, 보조 문구 분리, 선택 시 비활성 상태 재검사.
- `menu-bar-browser-regression.js`: 최근 프로젝트·메뉴 이동·실제 다음 편집기 배치·팔레트 명령 연결.
- `workspace-state-browser-regression.py`: 560px 접힌 메뉴의 이름/키/체크, 분리 창과 메인 창의 복귀 동작 이름, 분리 창에서의 원본 버튼 조회.
- 기존 우클릭·툴바·녹화·화면 상태 회귀 검사도 함께 실행한다.
