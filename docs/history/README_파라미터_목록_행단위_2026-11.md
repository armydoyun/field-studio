# 파라미터 목록을 행 단위로 그리기 (2026-11-16)

## 왜

`js/ui.js`의 `renderUniforms`가 약 900줄짜리 한 덩어리로, 무엇이 바뀌든 파라미터 목록 전체를 지우고 새로 만들었다.

- 프리셋을 부드럽게 바꿀 때 위치 패드(@pos) · 방향 패드(@dir)가 섞이면 0.5초마다 목록 전체를 새로 만들어 깜빡였다
- 값 되돌리기 · 값 묶음 적용처럼 값만 바뀌어도 목록 전체를 새로 만들었다
- 검색 칸에 글자를 칠 때마다 수십 개 행을 새로 만들었다
- 0.5초마다 도는 갱신(updateStats)이 슬라이더를 끄는 도중에 끼면 끌던 슬라이더까지 새로 만들어졌다
  (실제 사용에서는 초점이 목록 안에 있어 건너뛰었지만, 초점 없이 끄는 테스트 `parameter-pointer`가 가끔 실패한 원인)

## 어떻게

- **`buildRow(item, defaults)`**: 행 하나를 만든다(예전 루프 몸통 그대로). 뒤에 `js/parameter-row.js`로 옮겼다 —
  `ui.js`가 넘기는 ctx는 모든 항목이 getter이고, 다른 곳에서도 바뀌는 값(열린 연결 시트 · 삭제 되돌리기 · 조건 다시 그리기 …)은 `ctx.이름`으로 읽고 쓴다. `item`은 행이 계속 붙잡는 객체라, 행을 남긴 채 값이 바뀌면 같은 객체를 새 값으로 고친다.
- **행 캐시(`rowCache`)와 구조 열쇠(`rowKey`)**: 타입 · 설정 · 코드 주석(기본값 · 설명 · 묶음 · 조건) · 연결 설정 · 연결 시트 열림 · 잠금.
  열쇠가 같으면 행을 남긴다. 다르면 그 행만 버리고 다시 만든다.
- **값만 바뀐 행**: 행이 등록한 갱신 함수(`playViews`)로 보이는 값만 바꾼다. 모든 종류(숫자 · 켜기 · 선택지 · 각도 · 색 · 벡터 · 위치 · 방향 ·
  행렬 · 그라데이션 · 곡선 · 배열)가 갖고 있다. 갱신 함수가 `false`를 돌려주면(못 함) 그 행만 다시 만든다. 연결이 정하는 값은 연결 미터가 따로 따라간다.
- **거르기(검색 · 변경만 보기 · @if)**: 걸러진 행은 떼어 두기만 하고 캐시에 남긴다. 다시 보이면 같은 행을 쓴다.
  아직 만들지 않은 숨은 행은 브라우저가 한가할 때(`requestIdleCallback`) 하나씩 미리 만들어 둔다.
- **배치(`arrange`)**: 순서가 그대로면 DOM을 옮기지 않는다(옮기면 초점 · 누르고 있던 조작이 풀린다). 묶음 칸도 캐시한다.
- **행 버리기(`dropRow`)**: 그 행의 등록만 지운다 — 이름(배열은 `이름[i]`) 기준 등록표, 행이 만든 `parameterViews`, 패드 다시 그리기(`parameterControls.forget(row)`).

## 측정(파라미터 58개 예제, ms, SwiftShader)

| 동작 | 이전 | 행 단위(1차) | 미리 만들기 뒤(2차) |
|---|---|---|---|
| 검색 첫 글자 | 113~120 | 72~78 | 52~61 |
| 검색 지우기 | 41~43 | 18~21 | 14~16 |
| 탭 전환 | 59~64 | 29~31 | 24~25 |
| 값 묶음 적용 + 목록 반영 | 61~77 | 22 | 17~19 |
| 되돌리기 | 50~63 | 28~29 | 23~25 |

검색 첫 글자에 남은 비용은 새로 보이는 행 수십 개의 스타일 · 배치 계산이다(행은 이미 만들어져 있다).

## 검사

- `tests/parameter-rows-browser-regression.js`(새): 검색 · 값만 바뀜 · 되돌리기 · @if · 그라데이션 · 코드 주석 · 연결 시트 · 묶음 · 지우기에서 어떤 행이 남고 어떤 행이 바뀌는지.
- `tests/parameter-pointer-browser-regression.js`: 끄는 도중 목록 갱신이 끼어드는 경우를 늘 재현하게 했다(예전 코드에서 매번 실패).
- `tests/preset-morph-live-browser-regression.js`: 위치 패드가 섞인 전환도 목록을 다시 그리지 않는다.
