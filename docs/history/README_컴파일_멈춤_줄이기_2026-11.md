# 컴파일 때문에 화면이 멈추던 문제 줄이기 (2026-11-15 ~ 11-16)

코드를 고치거나 파라미터를 추가 · 삭제하면 화면이 몇 초씩 멈춘다는 보고에서 시작한 작업의 기록입니다.
PR: armydoyun/field-studio#116 · #117과 그 뒤 커밋.

## 원인

무거운 레이마칭 장면(파라미터 20개 · 버퍼 1개)에서 재 보니 멈춤은 거의 전부 **셰이더 컴파일**이었습니다.
WebGL은 컴파일 결과를 묻는 순간(`getShaderParameter` · `getProgramParameter`) GPU가 끝낼 때까지 메인 스레드를 멈춥니다.
여기에 같은 결과를 내는 **불필요한 컴파일**이 겹쳐 있었습니다.

| 경로 | 이전 | 이후 |
|---|---|---|
| 파라미터 추가 · 삭제 · 어노테이션 수정 | 3번 | 1번(뒤에서) |
| 무작위 · 프리셋 · 값 되돌리기 | 2번 | 0번 |
| Common 수정 | 패스마다 2번 | 1번 |
| 보관함 · Pack 열기 | 모든 셰이더 2번 | 1번(뒤에서) |
| 되돌리기 · 다시 실행(파라미터도 바뀔 때) | 모든 패스 | 바뀐 패스만 |

## 바뀐 구조

- **파라미터 등록은 셰이더를 바꾸지 않는다.** 선언은 코드가 가지므로(렌더러가 대신 넣지 않음) `defineUniform` · `removeUniform` ·
  `setUserUniforms`는 다시 컴파일하지 않고 코드의 선언 타입만 확인한다(`checkDeclaredTypes`).
- **프로그램 만들기를 두 단계로.** `startProgram`은 컴파일 · 링크를 GPU에 맡기기만 하고, `finishProgram`이 결과를 확인한다.
  `warm`(최종 소스 → 프로그램)에 미리 시작한 것을 두면 `createProgram`이 꺼내 쓴다. 남은 것은 적용이 끝날 때 `dropWarm`이 지운다.
- **뒤에서 컴파일(`renderer.prepareProject`).** `KHR_parallel_shader_compile`이 있으면 다음 적용이 다시 만들 프로그램만 미리 시작하고,
  끝났는지 멈추지 않고 물어(`COMPLETION_STATUS_KHR`) 끝나면 풀리는 Promise를 돌려준다. 확장이 없으면 `null` — 부르는 쪽은 바로 적용한다.
  편집기의 `applyWhenReady`가 이것을 쓰고, 그사이 코드가 바뀌거나 다른 적용이 일어나면(`warming` 번호) 기다리던 적용을 버린다.
- **시험 컴파일을 버리지 않기(`park`).** Common을 바꿀 때의 시험 컴파일, Pack 검사(`validatePortable`)가 만든 프로그램을 `warm`에 남겨
  곧 이어지는 실제 적용이 쓴다. 적용하지 않고 끝나면 `discardPrepared()`로 정리한다.
- **상태 줄의 걸린 시간.** `적용됨 · 걸린 시간 1.8초`, 뒤에서 컴파일했으면 `(뒤에서 컴파일 · 화면은 멈추지 않음)`.

## 바로 적용하는 길(그대로 둔 것)

- 공개 함수 `setProject()` · `example*()`: 결과를 바로 돌려주는 약속을 지킨다.
- 되돌리기 · 다시 실행: 적용 직후 파라미터 · 프리셋 · 연결을 차례로 되돌리므로, 기다리는 사이 다른 입력이 끼면 반쯤 되돌아간 상태가
  될 수 있다. 대신 바뀐 패스만 컴파일한다.
- 시작할 때 복원 · HTML 내보내기: 결과가 바로 필요하다.

## 한계와 확인

- 개발 환경(SwiftShader)에는 `KHR_parallel_shader_compile`이 없어 뒤에서 컴파일하는 효과는 실제 GPU에서만 확인할 수 있다.
  테스트(`tests/background-compile-browser-regression.js`)는 가짜 확장으로 "끝남"을 정해 흐름을 검사한다.
- 컴파일 시간 자체는 줄지 않는다. 결과가 나오기까지 걸리는 시간은 같고, 그동안 화면이 멈추지 않을 뿐이다.

## 함께 고친 것

- 프리셋을 부드럽게 바꾸는 동안 0.5초마다 파라미터 목록 전체를 다시 그리던 것: 행마다 등록한 갱신 함수(`playViews`)로 값만 바꾼다.
  (그 뒤 파라미터 목록을 행 단위로 그리게 되어 위치 · 방향 패드도 값만 바뀐다 — `README_파라미터_목록_행단위_2026-11.md`)
- 기다리는 사이 WebGL 컨텍스트를 잃으면 적용하지 않고 안내한다(컴파일 오류처럼 보이던 것).
- 실패한 컴파일이 같은 셰이더를 두 번 지우던 것.
