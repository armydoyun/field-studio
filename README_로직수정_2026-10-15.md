# Shader Art 로직 수정 · 2026-10-15

기준: 사용자가 첨부한 a.zip. 화면 디자인·에디터 기능 확장 없이 상태 전환과 실패 경로를 수정했다.

## 실행 소스 수정 범위

| 파일 | 방식 | 수정 위치 |
| --- | --- | --- |
| js/renderer.js | 특정 부분 수정 | buildFragment/compileFragment, replacePrograms, normalizeEntry, defineEntry/removeUniform, prepareUsers/applyPortable, applyProject 및 반환 API |
| js/pass-manager.js | 특정 부분 수정 | compilePass, setPasses/refreshPrograms/setPassFragment/restore, updatePasses 및 반환 API |
| js/studio.js | 특정 부분 수정 | showError, apply, adoptProject/exampleRaymarch, exportPack/importPack, studioExportPack 클릭 이벤트 |
| js/texture-input.js | 특정 부분 수정 | disposed 상태, add의 await 전후 검사와 ID 재검사, restore/dispose |
| 그 외 실행 파일 | 수정 없음 | HTML/CSS/기본 GLSL/입력/에디터 등 |

새 실행 모듈·외부 의존성 없음. JS 전체 169,489 → 169,328바이트(-161).

## 수정 내용과 이유

1. Run에서 뒤쪽 Buffer의 Uniform 위치 조회 등이 실패하면 이전 구현은 앞서 적용된 프로그램을 재컴파일해 되돌렸으며 FBO/누적 Texture가 사라질 수 있었다. Renderer.applyProject와 PassManager.updatePasses로 준비 후 교체를 수행한다. 소스·채널 변경은 기존 FBO를 보존한다. 이름·순서·크기·포맷 변경은 기존처럼 패스 전체를 교체한다.
2. 사용자 Uniform 추가/삭제와 Pack 적용에서 Image를 먼저 확정하던 순서를 변경했다. Image 후보를 준비하고 Buffer 준비가 성공한 뒤 확정한다. 실패 시 후보만 해제하고 레지스트리를 되돌린다. 롤백을 위한 재컴파일에 의존하지 않는다.
3. Ray Starter가 현재 작업의 GLSL에 새 Uniform을 주입하던 것을 제거했다. 새 프리셋과 사용자 Uniform 목록을 applyPortable로 함께 적용한다. 기존 등록 타입 충돌은 계속 거부한다.
4. precision lowp/mediump/highp, 추가 공백·줄바꿈, 주석, 쉼표로 묶은 Uniform 선언을 처리한다. 소스 위치를 보존한 주석 마스킹을 사용한다. 같은 줄에 코드가 이어질 때도 주입된 선언과 원본 오류 줄을 구분한다. 완전한 GLSL 전처리기/파서를 추가한 것은 아니다.
5. 일반 등록과 Pack 등록의 이름·값·슬라이더 검증을 normalizeEntry 한곳으로 통합했다. 일반 등록도 사용자 Uniform 64개 제한을 지켜, 직접 저장한 Pack을 개수 제한 때문에 다시 열지 못하는 상황을 방지한다.
6. Pack Export 클릭의 event.currentTarget을 await 전에 보관한다. 비동기 완료 후 버튼 복구 시 null 접근을 방지한다.
7. Pack Export는 이미지 읽기 전에 프로젝트·탭·설정·이미지 파일 참조를 고정한다. 읽는 동안 편집해도 서로 다른 시점의 소스와 이미지가 섞이지 않는다.
8. Pack Import는 선택 탭을 확정한 뒤 저장한다. 프리셋/Pack의 편집 상태 반영을 adoptProject로 통합했다.
9. 이미지 디코딩 중 dispose되면 완료된 bitmap을 닫고 GPU 자원을 만들지 않는다. 같은 ID의 동시 등록도 await 이후 다시 검사해 기존 자원을 덮어쓰지 않는다.

## 검증

- 신규 tests/logic-regression.js: 19개 통과. 같은 검사를 수정 전 a.zip에 실행하면 3개 통과/16개 실패. 이는 오류 수가 아니라 테스트 시나리오 수다.
- tests/architecture-regression.js: 44개 통과. 기존의 컴파일 호출 횟수 기반 실패 주입을 새 준비 순서에 맞췄고, 원본 GPU 객체 보존을 검사한다.
- texture-regression, sampling-regression, pack-settings-freeze, custom-modal-regression, ui-matte-regression, default-template-regression, folding-rollback-regression, shader-art-starter-regression 통과.
- 실행 JS 11개 문법 검사. 수정된 Python 브라우저 테스트 문법 검사.
- runtime-integrity.js와 SHA-256 목록은 수정본 기준으로 갱신·검증한다.
- 브라우저 테스트의 Renderer 모의 객체를 applyProject 계약에 맞췄다. 실제 브라우저/GPU 테스트는 실행하지 못했다. Chromium 설치 다운로드가 정상 파일을 반환하지 않았다.

새 회귀 테스트는 production 모듈을 실행하지만 DOM/WebGL/비동기 경계를 모의한다. 실제 GLSL 드라이버 컴파일, 화면 배치, 실제 IndexedDB 동작의 검증을 대신하지 않는다.

## 로컬 확인

```bash
node tests/logic-regression.js
node tests/architecture-regression.js
node tests/runtime-integrity.js
```

실제 브라우저에서는 tests/gpu-validation.html을 실행하고, Ray Starter 전환·Pack 재가져오기·Buffer 피드백 편집을 확인한다.
