# UX 1차: 작업 상태와 패스 연결 · 2026-10-15

## 변경

1. 실행·보관·내보내기를 분리했다. 기존 적용 상태는 ‘실행 반영됨’으로 표시하고, 별도의 소스 보관 상태는 보관 전/대기/미적용 편집본 보관/실행 소스 보관/실패로 구분한다. 보관 실패는 다른 상태 메시지로 가려지지 않는다. 브라우저 보관 상태는 소스·채널 구성에 관한 것이며 파라미터·이미지까지 포함하는 전체 작업 파일을 뜻하지 않는다. 파일 표시는 마지막 다운로드 요청의 파일명이다. 운영체제의 실제 저장 완료나 이후 변경 포함을 주장하지 않는다.
2. 패스 순서를 바꿔 current 참조가 previous로 변환되면 대상 채널과 입력 버퍼를 지속 안내한다. 변환이 없을 때도 이를 명시하고, 기존 Undo를 사용하는 ‘변경 되돌리기’를 제공한다. 적용 실패 시 미적용 상태를 표시하고 재실행 성공 시 갱신한다. 새 편집이나 다른 구조 변경을 시작하면 이전 안내를 지워 엉뚱한 작업을 되돌리지 않도록 한다.
3. 자동 완성에서 Ray Marching 전용 고정 이름을 제거했다. 공통 GLSL/엔진 이름, 현재 등록된 사용자 Uniform, 현재 패스 코드에 쓰인 식별자를 후보로 제공한다. 주석·문자열·전처리문은 제외한다. 프로젝트 전환과 Uniform 삭제는 다음 후보 요청에 즉시 반영된다. 이는 편집 보조용 이름 제안이며 GLSL 의미 분석기는 아니다. 함수 탐색과 이름 후보의 주석 제거는 기존 모듈 내부에서 공유한다.
4. 버퍼 삭제 전에 다른 패스에서 참조하는 연결 수를 표시하고 버튼 설명에 해제될 채널을 열거한다. 자기 자신의 피드백 연결은 외부 영향 수에서 제외한다. 삭제 후 해제된 연결을 안내하고 Undo로 소스·버퍼·연결을 함께 복원한다. 기존 확인 모달을 추가로 늘리지 않았다.
5. 코드 제목에 ‘편집’, 뷰포트 및 코드 제목 옆에 ‘미리보기’를 표시한다. 최종 Image로 돌아와도 Buffer 편집 대상은 유지되므로 두 대상을 독립적으로 확인할 수 있다.

새 외부 의존성, 실행 파일, AMD 모듈을 추가하지 않았다. 13개 실행 파일/10개 AMD 모듈을 유지한다. 실행 오류 상태는 저장 실패 및 파일 내보내기 안내와 독립적으로 유지된다.

## 검증

`node tests/workflow-ux-regression.js`: 새 동작 16개 검증 통과. 저장 실패와 컴파일 실패의 독립성, 내보내기 준비 실패, 연결 전환과 전체 되돌리기, 자기 참조 제외, 안내 만료, 재실행 후 안내 갱신, 문맥에 따른 이름 후보 변경을 포함한다.
기존 20개 회귀 검증 스위트 통과. 기존 최종 Image 복귀 검증에 편집/미리보기 대상 분리 확인을 추가했다. 전체 JavaScript/Python 구문 검사, 실행 파일/전체 파일 SHA-256, ZIP 무결성을 검증했다.
실제 브라우저 화면을 확보하지 못했으므로 검증 범위는 정적 HTML/CSS 및 모의 DOM/WebGL에서 실행한 실제 모듈 동작이다.
